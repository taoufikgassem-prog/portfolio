UI Actions dans ServiceNow : personnaliser les interactions utilisateur

Par Taoufik GassemPublié le 8 octobre 2025Mis à jour le 8 octobre 20257 min de lecture

Sommaire

  1. Qu'est-ce qu'une UI Action
  2. Boutons, liens et éléments de menu
  3. Conditionner l'affichage

  5. Checklist UI Actions
  6. Conclusion

Les UI Actions permettent d'ajouter des boutons, des liens ou des éléments de menu personnalisés sur les formulaires et les listes de ServiceNow, déclenchant une action métier spécifique lorsque l'utilisateur interagit avec eux.

Qu'est-ce qu'une UI Action

Une UI Action associe un élément d'interface (bouton, lien, entrée de menu) à un script qui s'exécute lorsque l'utilisateur clique dessus. Cette action peut modifier l'enregistrement courant, rediriger vers une autre page, ou déclencher un traitement plus complexe côté serveur.

Boutons, liens et éléments de menu

ServiceNow permet de configurer une UI Action pour qu'elle apparaisse sous différentes formes : bouton de formulaire, lien contextuel, ou élément du menu d'actions liées. Le choix de la forme dépend de la fréquence d'utilisation attendue et de l'importance de l'action pour l'utilisateur.

Conditionner l'affichage

Une UI Action peut être affichée uniquement dans certaines conditions : état de l'enregistrement, rôle de l'utilisateur, ou valeur d'un champ spécifique. Cette possibilité évite de proposer des actions non pertinentes ou non autorisées à un utilisateur donné.

Exemple : une action de clôture rapide

Sur un incident, une UI Action de "clôture rapide" pourrait n'apparaître que pour les utilisateurs disposant du rôle adéquat, et uniquement lorsque l'incident est dans un état permettant sa clôture, évitant ainsi des actions incohérentes avec le cycle de vie défini.

Sécuriser les UI Actions

Comme pour les Client Scripts, il est essentiel de rappeler qu'une condition d'affichage côté interface ne remplace pas un contrôle de sécurité réel. Les vérifications critiques doivent être dupliquées dans le script serveur associé à l'UI Action, ou contrôlées via des ACL appropriées.

Checklist UI Actions

  • Chaque UI Action répond à un besoin métier clairement identifié.
  • Les conditions d'affichage reflètent les rôles et états pertinents.
  • Les contrôles de sécurité critiques sont également appliqués côté serveur.
  • Le nombre d'UI Actions proposées reste raisonnable pour ne pas surcharger l'interface.
Une UI Action bien conçue simplifie une tâche répétitive sans complexifier l'ensemble de l'interface pour les autres utilisateurs.

Conclusion

Les UI Actions offrent un moyen efficace de personnaliser les interactions utilisateur dans ServiceNow, à condition d'être utilisées avec discernement et accompagnées des contrôles de sécurité nécessaires côté serveur.
