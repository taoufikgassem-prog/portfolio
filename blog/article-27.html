Automatisation des tests

Intégrer les tests automatisés dans GitLab CI

GitLab est souvent associé à deux usages distincts qu'il convient de bien différencier : la gestion de version du code et des scripts de test, et l'intégration continue (CI) qui automatise l'exécution de ces tests à chaque évolution du code. Cet article clarifie cette distinction dans le contexte des systèmes embarqués.

GitLab comme outil de gestion de version

GitLab permet, dans son usage le plus courant, de versionner le code source, les scripts de test automatisés et leurs évolutions successives. Cette gestion de version est indispensable pour tracer les modifications, revenir à une version antérieure en cas de problème, et permettre à plusieurs contributeurs de travailler en parallèle.

Le concept de pipeline CI

Au-delà de la gestion de version, GitLab propose des fonctionnalités de pipeline d'intégration continue (CI), qui permettent de déclencher automatiquement des actions, comme l'exécution de tests, à chaque modification du code versionné. Ce mécanisme est largement répandu dans le développement logiciel classique.

Spécificités des systèmes embarqués

Dans le contexte des systèmes embarqués automobiles, l'exécution automatique de tests via un pipeline CI se heurte souvent à des contraintes spécifiques : nécessité de matériel physique (bancs HIL, calculateurs réels), disponibilité limitée de ces moyens, et temps d'exécution parfois longs pour certains scénarios. La mise en œuvre d'un pipeline CI complet, déclenchant automatiquement des campagnes sur banc physique, nécessite une infrastructure dédiée et n'est pas systématiquement en place sur tous les projets.

Distinguer l'usage réel de l'usage potentiel

Il est important de ne pas confondre l'usage de GitLab pour la gestion de version des scripts de test, très répandu, avec la mise en place effective d'un pipeline CI déclenchant des campagnes de validation matérielle automatisées, qui reste un projet d'infrastructure à part entière.

Une démarche progressive

La mise en place d'une intégration continue pour des tests embarqués se construit généralement par étapes : d'abord la gestion de version rigoureuse des scripts, puis l'automatisation de tests sur des moyens de simulation (SIL), avant d'envisager, si l'infrastructure le permet, une automatisation partielle sur des moyens matériels (HIL).

Checklist d'intégration continue pour systèmes embarqués

  • Les scripts de test sont versionnés de façon rigoureuse dans GitLab.
  • Le niveau réel d'automatisation (gestion de version seule, ou pipeline CI complet) est clairement identifié.
  • Les contraintes matérielles spécifiques aux systèmes embarqués sont prises en compte avant de viser une CI complète.
  • La démarche d'automatisation progresse par étapes maîtrisées plutôt que par un déploiement complet immédiat.
Utiliser GitLab pour versionner des scripts de test n'équivaut pas automatiquement à disposer d'un pipeline d'intégration continue opérationnel sur banc matériel.

Conclusion

GitLab constitue un outil précieux pour la gestion de version des scripts de test automobiles, et peut, selon l'infrastructure disponible, être étendu vers des pratiques d'intégration continue plus poussées. Cette distinction doit rester claire pour éviter toute confusion sur le niveau réel d'automatisation en place.
