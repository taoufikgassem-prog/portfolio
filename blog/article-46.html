Update Sets : gérer les déploiements dans ServiceNow

Par Taoufik GassemPublié le 19 novembre 2025Mis à jour le 19 novembre 20258 min de lecture

Sommaire

  1. Qu'est-ce qu'un Update Set

  3. Pièges classiques à éviter

  5. Checklist Update Sets

Les Update Sets sont le mécanisme standard de ServiceNow pour transporter des modifications de configuration entre différentes instances (développement, test, production). Une gestion rigoureuse des Update Sets est indispensable pour des déploiements fiables.

Qu'est-ce qu'un Update Set

Un Update Set regroupe l'ensemble des modifications de configuration (scripts, formulaires, règles) réalisées pendant une session de travail, afin de pouvoir les exporter et les importer sur une autre instance, généralement dans le cadre d'un processus de développement, test puis mise en production.

Le cycle de vie d'un Update Set

Un Update Set est généralement créé en début de développement, complété au fur et à mesure des modifications, puis marqué comme complet avant son export. Sur l'instance cible, il est importé puis appliqué (committed) après vérification de son contenu.

Pièges classiques à éviter

Un piège fréquent consiste à travailler sur plusieurs sujets simultanément dans un même Update Set, rendant difficile un déploiement partiel ou une revue claire des modifications. Un autre piège concerne les dépendances entre composants, qui doivent être incluses dans le même Update Set pour éviter des erreurs de configuration incomplète sur l'instance cible.

Le cas des Update Sets qui se chevauchent

Lorsque plusieurs Update Sets modifient les mêmes composants dans un ordre différent de celui prévu, des conflits peuvent apparaître lors de l'application sur l'instance cible. Une coordination claire entre contributeurs limite ce risque, en particulier sur des instances partagées par plusieurs développeurs.

Bonnes pratiques de gestion

Il est recommandé de créer un Update Set dédié par sujet fonctionnel, de nommer clairement chaque Update Set selon son contenu, et de documenter les dépendances éventuelles avec d'autres Update Sets avant tout déploiement en production.

Checklist de gestion des Update Sets

  • Chaque Update Set correspond à un sujet fonctionnel cohérent et clairement nommé.
  • Le contenu de l'Update Set est vérifié avant son export vers l'instance cible.
  • Les dépendances entre composants sont identifiées et documentées.
  • L'application de l'Update Set en production est précédée d'un test sur une instance intermédiaire.
Un Update Set mal délimité rend le déploiement imprévisible : ce qui est facile à corriger en développement devient risqué en production.

Conclusion

Les Update Sets sont un mécanisme puissant mais exigeant en discipline pour gérer les déploiements de configuration dans ServiceNow. Une organisation rigoureuse, sujet par sujet, limite considérablement les risques lors des mises en production.
